# AGENTS.md

Читай этот файл целиком перед каждым шагом. Полное ТЗ — в `ТЗ для ИИ-агента.pdf`
в корне репозитория.

## Как работать с ТЗ

- ТЗ — 15 шагов по порядку, у каждого есть задача, требования и критерии
  приёмки. Шаги 1–8 — MVP (этап 1), 9–12 — рост (этап 2), 13–14 — монетизация
  (этап 3), 15 — сопровождение.
- Шаги выполняются по порядку. После шага: все гейты шага зелёные → дописать в
  `TODO.md` раздел «Шаг N» со всем, что нужно от человека (приёмка, данные,
  тексты юриста, решения, ручные действия) → коммит → сразу следующий шаг, не
  дожидаясь приёмки. Человек принимает шаги пакетом позже.
- Если шаг упирается в решение человека по правилу 9 (деньги, реклама,
  юридические тексты) — сделать всё, что от решения не зависит, поставить
  заглушку `TODO(...)`, вынести вопрос в `TODO.md` и идти дальше; остановиться,
  только если без ответа нельзя сделать следующий шаг.
- Раздел ТЗ «Сценарии и крайние случаи» входит в приёмку: у каждой строки есть
  номер шага. Выполняя шаг N, закрой все строки с номером N и напиши на них
  тесты, где это возможно. Строки «Плана Б» нужны, только если человек выбрал
  план Б (см. «Решения»).
- Человек принимает шаг сам: открывает сайт, смотрит отчёт тестов, проверяет
  код в точках риска (деньги, офферы, внешние ссылки).
- Всё, что агент не смог или где спросил, решает человек и записывает в раздел
  «Решения» ниже. Эти решения обязательны для следующих шагов.

## Правила для агента

1. Никаких ссылок на букмекеров, казино и любые гемблинг-сайты вне модуля
   офферов из шага 13. Модуль выключен по умолчанию: `OFFERS_ENABLED=false`.
2. Никаких казино, слотов, офшорных букмекеров, «прогнозов» и обещаний
   выигрыша. Только математика ставок и справка.
3. Не придумывать данные о букмекерах: правила, бонусы, юрлица, erid. Только из
   файлов в `data/`, которые заполняет человек. Нет данных — заглушка и пометка
   `TODO(data)`.
4. Все расчёты — чистые функции с юнит-тестами. Деньги и коэффициенты считать
   точной десятичной арифметикой, без `number` с плавающей точкой; округлять
   только итог.
5. Язык интерфейса и текстов — русский, простой, без кликбейта и призывов
   играть.
6. После каждого шага прогнать линтер, проверку типов, тесты и сборку. В конце —
   отчёт: что сделано, как проверить руками, что осталось, какие решения принял
   сам.
7. Не менять стек и структуру из раздела «Контекст» без согласования.
8. Секреты и токены — только через переменные окружения, в репозиторий не
   коммитить.
9. Если требование про деньги, рекламу или юридические тексты неоднозначно —
   остановиться и спросить, а не угадывать.
10. Шаг закрыт, только когда выполнены его критерии приёмки и все строки раздела
    «Сценарии и крайние случаи» с его номером.
11. Визуальный стиль — по `DESIGN.md` в корне: цвета, шрифты, отступы, радиусы
    и компоненты брать оттуда, токены оформить CSS-переменными. Из него берётся
    только стиль: название, логотип, пункты меню и тексты того сайта, с которого
    снят референс, не переносить. Если `DESIGN.md` противоречит ТЗ (контраст
    AA, шрифты локально, Lighthouse, 18+, без образов для детей) — прав ТЗ.
12. Версии зависимостей (Nuxt, Node, decimal.js, Vitest, Playwright и т. д.) и
    их API брать из Context7, а не из памяти: актуальная стабильная мажорная
    версия. Выбранные версии записать в отчёт шага.

## Контекст

### Продукт

Русскоязычный сайт с калькулятором системы и экспресса для игроков легальных
букмекеров России, 18+, в основном с телефона. Позже — разборы систем, мелкие
калькуляторы, виджет для других сайтов и офферы легальных БК. Офферы
включаются только после регистрации сайта как СМИ.

### Ограничения

- Хостинг только в России: Cloudflare, Hetzner, OVH и DigitalOcean российские
  провайдеры замедляют.
- Без аккаунтов и форм с персональными данными. Аналитика — только Яндекс
  Метрика и только после согласия на cookie. Без Google Analytics и сторонних
  виджетов, которые передают данные за рубеж.
- Страницы отдаются готовым HTML: Яндекс и Google должны видеть текст и пример
  расчёта без JavaScript.
- Сначала телефон. Lighthouse на телефоне от 90, LCP до 2,5 с, CLS до 0,1, INP
  до 200 мс.
- Внешние ссылки — только на домены из `data/allowlist.json`. Ссылка на домен
  вне списка ломает сборку.

### Архитектура

Офферы — единственное место, где сайт ведёт на букмекера, и только через
`/go/<id>`. Всё юридически важное (гео, erid, срок действия, выключатель)
проверяется там. Офферы никогда не показываются в виджете и `/embed/`.

### Стек

| Слой      | Выбор                                                             |
| --------- | ----------------------------------------------------------------- |
| Фреймворк | Nuxt актуальной мажорной версии, Vue 3 Composition API, TypeScript strict |
| Стили     | SCSS и CSS-переменные, без UI-кита                                |
| Состояние | composables; Pinia — только если понадобится                      |
| Деньги    | decimal.js или big.js                                             |
| Тесты     | Vitest, Playwright, @axe-core/playwright                          |
| Качество  | ESLint, Prettier, vue-tsc, Lighthouse CI                          |
| Сервер    | Nitro (node-server) за Nginx на VPS в России (`/api/geo`, `/go/:id`) |
| Деплой    | GitHub Actions → SSH на VPS; staging под паролем и noindex        |

### Структура репозитория

```
/

│  ├─ components/

│  │  ├─ legal/                  # 18+, предупреждения, пометка «Реклама», выходные данные СМИ
│  │  └─ offers/                 # блок офферов (шаг 13), выключен по умолчанию
│  ├─ composables/               # useSystemCalc, useShareState, useConsent
│  └─ lib/calc/                  # чистые функции расчёта, без Vue
├─ server/
│  ├─ api/geo.get.ts             # страна и значение выключателя офферов
│  ├─ api/stat.post.ts           # счётчики показов без cookie и IP
│  └─ routes/go/[id].get.ts      # переход на оффер, счётчик кликов
├─ data/
│  ├─ bookmakers.json            # БК и их правила, заполняет человек
│  ├─ offers.json                # офферы с erid, сроками и юрлицом
│  ├─ allowlist.json             # разрешённые внешние домены
│  ├─ site.json                  # выходные данные СМИ, предупреждения, стоп-лист слов
│  └─ partners.json              # партнёры виджета, только в плане Б
├─ scripts/                      # check:offers, check:links, check:rules, report
└─ tests/
   ├─ unit/                      # Vitest
   └─ e2e/                       # Playwright
```

### Адреса страниц

Все адреса — со слешем на конце.

- `/` — калькулятор системы
- `/kalkulyator-ekspressa/` — калькулятор экспресса
- `/sistema-<k>-iz-<n>/` — страница системы, например `/sistema-3-iz-5/`
- `/chto-takoe-sistema-v-stavkah/` — разбор для новичков
- `/bk/<slug>/kak-schitaetsya-sistema/` — правила конкретного БК
- `/kalkulyatory/<name>/` — маржа, сложение коэффициентов, догон, конвертер,
  фрибет
- `/vidzhet/` и `/embed/sistema/` — страница виджета и сам виджет
- `/o-proekte/`, `/reklama/`, `/politika-konfidencialnosti/`,
  `/otvetstvennaya-igra/` — служебные

`AGENTS.md` в задании.

Параллельная работа:

- Сабагентов можно запускать несколько одновременно. Независимые задачи плана
  отправлять одной пачкой, не дожидаясь каждой.
- Последовательно — только то, чему действительно нужен результат предыдущей
  задачи (например, UI калькулятора ждёт движок `lib/calc`).
- Перед запуском составить план файлов: какой агент какие файлы создаёт и
  правит. Два агента одновременно не правят один файл; общие файлы
  (`package.json`, `nuxt.config.ts`, конфиги CI, `AGENTS.md`) правит только
  главный агент — до или после пачки.

## Решения

Сюда человек записывает решения по вопросам, которые агент не смог закрыть
сам. Формат: дата, шаг, вопрос → решение.

- 2026-10-25, шаг 12: план А или план Б (лицензии на виджет) → план А. Строки
  «Плана Б» из сценариев не делать, `data/partners.json` не создавать.
- 2026-10-25, шаг 1: название сайта и домен → keflab.ru. Шапка, подпись-ссылка
  виджета, `site.json`, canonical и sitemap используют этот домен.
- 2026-10-25, шаг 1: версии Node, Nuxt и остальных зависимостей → актуальные
  стабильные из Context7 (правило 12), пакетный менеджер — npm.
- 2026-10-25, шаг 2: decimal.js или big.js → big.js: в несколько раз легче, а
  его операций (сложение, умножение, деление, округление «половина вверх»)
  достаточно для ТЗ.
- 2026-10-25, шаг 3: визуальный стиль → `DESIGN.md` (правило 11).
- 2026-10-25, шаг 1 (решение агента): TypeScript 6, а не 7 — vue-tsc 3 не
  запускается с TypeScript 7. Пересмотреть, когда vue-tsc поддержит 7.
- 2026-10-25, шаг 1 (решение агента): Node 24 в CI (`.nvmrc`), минимум
  `>=22.22.3` (требование Nuxt 4.6). Скрипты в `scripts/` — `.ts`, запускаются
  `node` напрямую (type stripping): без enum/namespace, импорты с `.ts`.
- 2026-10-25, шаг 1 (решение агента): схемы данных — `data/schema.ts` (zod),
  формат allowlist — `{ "domains": string[] }`, поддомены разрешённого домена
  разрешены, keflab.ru разрешён всегда.
- 2026-10-25, шаг 1 (решение агента): `router.options.strict` не включаем — с
  ним каждой странице нужен ручной `path` со слешем. Страницы отвечают и со
  слешем, и без; 301 на адрес со слешем и canonical делаются на шаге 6.
- 2026-10-25, шаг 2 (решение агента, ВРЕМЕННОЕ — ждёт человека, см. TODO.md):
  лимит ставки 10 000 000 ₽ относится к общей ставке; в режиме «на одну
  комбинацию» ставка × C(N, K) > 10 000 000 → ошибка `total_stake_too_large`.
- 2026-10-25, шаг 2 (для шага 3): итог системы — главное число; выплаты по
  строкам округляются отдельно и могут расходиться с итогом на копейки
  (`rowsDifferFromTotal`) — подписать это в таблице. Разбивка 8 из 16 —
  12 870 строк (~42 мс на Node): не пересчитывать на каждую клавишу (пауза
  150 мс или Web Worker), таблицу рисовать постранично/виртуально.
- 2026-10-25, шаг 2: движок — `app/lib/calc/` (импорт из `~/lib/calc`).
  Сценарии считаются без перебора: min/max на m наименьших/наибольших
  коэффициентах (монотонность e_k), проверено тестом против полного перебора.
- 2026-10-25, шаг 3 (решение агента): новое событие по умолчанию — «ждём»:
  калькулятор чаще нужен до матча, итог тогда «ещё не рассчитан», а диапазон —
  во вкладке «Сценарии». Сравнение (экспресс / система / одиночные) — при той
  же общей ставке.
- 2026-10-25, шаг 3: калькулятор — `app/components/calc/SystemCalculator.vue`
  (props `n`, `k` для страниц систем шага 9), состояние —
  `app/composables/useSystemCalc.ts`, тексты — `app/lib/texts.ts`,
  форматирование — `app/lib/format.ts`. big.js в strict-режиме: в компонентах
  сравнивать только со строками (`.gt('0')`, не `.gt(0)`) — иначе 500 на SSR.
- 2026-10-25, шаг 3: в шаблонах Vue не писать многострочные обработчики
  событий — Prettier (без точек с запятой) склеивает их в невалидный код;
  выносить в функцию.
- 2026-10-25, шаг 4: формат ссылки — `?s=3000&m=c&k=2&e=1.8w,2.1w,1.65l`
  (`app/lib/share-state.ts`); ссылка важнее localStorage и применяется уже на
  сервере; битая ссылка → расчёт по умолчанию, мягкое сообщение и чистый
  адрес; посторонние параметры (utm) при обновлении адреса отбрасываются.
  Страница с параметрами — `noindex, follow`, canonical — адрес без
  параметров. В скриптах проверок неразрывный пробел писать как `\u00A0`, а
  не символом (ESLint no-irregular-whitespace).
- 2026-10-25, шаг 5: крошки — `app/components/Breadcrumbs.vue` (props
  `items: {label, to?}[]`), у каждой страницы кроме главной. В шапке —
  навигация «Система / Экспресс / Разбор». Таблица типов систем —
  `app/lib/system-table.ts` (окупаемость при одинаковых коэффициентах 2,00 и
  1,80). Числа в текстах статей берутся из движка (`app/components/article/
  examples.ts`), не набираются руками. Экспресс: при «ждём» общий
  коэффициент и «если всё зайдёт» считаются с допущением «ждём зайдёт».
- 2026-10-25, шаг 5: скрипты-гейты — `scripts/gates/*.mjs` (общий запуск
  сервера и видимый текст — `lib-server.mjs`); стоп-слова из `data/site.json`
  проверяются по видимому тексту всех страниц (`stopwords.mjs`).
